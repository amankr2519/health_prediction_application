# Health Prediction Application — Project Requirements

## 1. Project Overview

Build a web-based Health Prediction Application that collects and manages patient information, stores blood test results, and generates AI-based health observations using an external AI API.

The application will use React and Tailwind CSS for the frontend, Python FastAPI for the backend, MongoDB Atlas for persistent storage, and Groq API for AI integration.

## 2. Technology Stack

| Component | Technology |
|---|---|
| Frontend | React |
| CSS Framework | Tailwind CSS |
| Backend | Python |
| API Framework | FastAPI |
| Database | MongoDB Atlas |
| Database Driver | PyMongo |
| AI Integration | Groq API |
| HTTP Client | Axios |
| API Documentation | FastAPI Swagger UI |
| Version Control | Git and GitHub |

## 3. Functional Requirements

### 3.1 Patient Information Management

The application must collect and manage the following fields for each patient:

- Full Name
- Date of Birth
- Email Address
- Glucose
- Haemoglobin
- Cholesterol
- Remarks (generated by AI)

### 3.2 CRUD Operations

The application must support all four CRUD operations.

#### Create

- Allow users to add a patient record.
- Validate the submitted information before saving it.
- Generate AI remarks through the external AI API when integration is enabled.
- Store the patient information and remarks in MongoDB.

#### Read

- Display all saved patient records.
- Allow users to retrieve an individual patient record.
- Display patient information and AI-generated remarks.

#### Update

- Allow users to edit an existing patient record.
- Save changes to MongoDB.
- Support updating a patient's email address as required by the assignment.

#### Delete

- Allow users to delete a patient record.
- Confirm deletion before proceeding.
- Refresh the displayed records after deletion.

### 3.3 User Interface

The application must provide a simple, clean, and user-friendly interface.

The interface should include:

- A patient dashboard.
- A form for adding patient information.
- An interface for editing existing records.
- A table displaying patient records.
- Actions for viewing, editing, and deleting records.
- Clear validation messages and API error messages.
- A section or column for AI-generated remarks.
- Loading and success states for relevant operations.

### 3.4 Data Validation

The application must validate patient information before accepting it.

Validation requirements include:

- Full name must not be empty.
- Email addresses must follow a valid format.
- Date of birth must be a valid calendar date.
- Date of birth must not be in the future.
- Dates must support the assignment's `dd/mm/yyyy` format.
- Glucose, haemoglobin, and cholesterol values must be numeric.
- Invalid data must produce clear error messages.
- Backend validation must be implemented independently of frontend validation.

The supplied test records must not be silently corrected or modified.

### 3.5 Persistent Storage

- Use MongoDB Atlas as the database.
- Create a database named `health_prediction_db`.
- Store patient records in a collection named `patients`.
- Assign a unique identifier to each patient record.
- Preserve records when the application restarts.
- Store AI remarks and their generation status.
- Handle database connection failures gracefully.

### 3.6 AI API Integration

The application must integrate with an external AI API to generate remarks from patient blood test values.

The planned provider is Groq API.

Requirements:

- Send relevant patient blood test values to the AI API.
- Generate explanatory remarks based on the supplied values.
- Store the returned remarks in MongoDB.
- Display the remarks in the patient records table.
- Handle AI API errors and unavailable services.
- Provide a way to retry failed AI requests.
- Never expose API keys in frontend code or public repositories.

AI-generated observations must not be presented as confirmed medical diagnoses. Clinical interpretation requires appropriate units, reference ranges, and professional medical assessment.

AI integration will be implemented after the core CRUD functionality is complete.

## 4. Backend API Requirements

The FastAPI backend should expose REST endpoints for patient management.

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | Check that the API is running |
| GET | `/health` | Check application and database connectivity |
| POST | `/api/patients` | Create a patient record |
| GET | `/api/patients` | Retrieve all patient records |
| GET | `/api/patients/{id}` | Retrieve one patient record |
| PUT | `/api/patients/{id}` | Update a patient record |
| DELETE | `/api/patients/{id}` | Delete a patient record |
| POST | `/api/patients/{id}/remarks` | Generate or retry AI remarks |

The backend must:

- Validate request data.
- Return appropriate HTTP status codes.
- Return clear error messages.
- Handle invalid patient IDs.
- Convert MongoDB identifiers into JSON-compatible values.
- Keep database and AI integration logic separate from route handlers.
- Read sensitive configuration from environment variables.

## 5. Database Requirements

Each patient document should contain fields equivalent to:

```json
{
  "full_name": "Robyn Pears",
  "date_of_birth": "1960-01-28",
  "email": "robyn@gmail.com",
  "glucose": 232,
  "haemoglobin": 13.5,
  "cholesterol": 180,
  "remarks": null,
  "remarks_status": "pending",
  "created_at": null,
  "updated_at": null
}
```

The example illustrates the proposed document structure. Actual timestamps must be generated by the application, and remarks should be populated when AI integration succeeds.

Suggested remarks statuses:

- `pending`
- `completed`
- `failed`

## 6. Frontend Requirements

The React application should:

- Communicate with the FastAPI backend through HTTP requests.
- Display patient records retrieved from MongoDB through the backend.
- Submit validated patient information.
- Display backend validation errors.
- Support editing and deleting records.
- Display AI remarks and their status.
- Refresh the displayed data after successful operations.
- Use Tailwind CSS for responsive styling.
- Keep API communication logic separate from UI components.

## 9. Security Requirements

- Store MongoDB credentials in environment variables.
- Store the Groq API key in environment variables when AI integration is added.
- Exclude `.env` files from GitHub.
- Provide an `.env.example` file containing placeholders only.
- Never expose database credentials or API keys in frontend code.
- Restrict MongoDB Atlas network access appropriately.
- Avoid logging sensitive patient information unnecessarily.
